# Validation verifies formally in two layers

Validation runs the `formal-verification` skill before it exercises the running application. Layer 1 runs on every Task: each Acceptance Criterion becomes a written property, its example and generated-input tests are audited and run, every changed executable line must be reached, and manual mutation probes must each be killed or given a disposition. Layer 2 runs only when the change touches concurrency, a state machine, retries, idempotency or money: a TLA+ model checked by TLC. The research behind the methods, thresholds and triggers is in `docs/research/formal-verification.md` and `docs/research/verification-skills.md`.

Development writes the tests, so they stay in the repository and run in CI; Validation only audits and measures them. Validation adds no dependency to the project: generated-input tests use the project's library or a seeded loop, coverage uses Ruby's own `Coverage` module or the JavaScript runner's LCOV output, and mutation uses manual probes, because `mutant` needs a paid license for private code. Mutation moved out of Code Review, which now leaves the Workspace untouched. The cost is a longer Validation, one Escalation whenever a needed tool such as Java for TLC is missing, and a mutation score that gives context but never decides the verdict, since the score predicts real faults only weakly once suite size is controlled.
