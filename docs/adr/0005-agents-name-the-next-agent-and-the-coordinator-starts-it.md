# Agents name the next agent, and the Coordinator starts one at a time

Each agent decides which agent comes next and writes it on the `Next:` line of its report; the Coordinator checks that line against the agent's files and starts that agent. At most two Claude sessions of a Task are alive, the Coordinator's and the running agent's, and every finished worker closes. In ENG-4463 the Coordinator kept every finished worker open with `worker-retain`, so the sessions of five cycles stayed alive until delivery and the machine ran out of memory. We rejected letting each agent start the next one, because in Orca the agent that runs `worker-start` becomes that worker's coordinator and must stay alive until it reports, so the whole chain of agents would stay alive. The cost is that a finished session cannot be reopened for a follow-up question: each correction goes to a new session, and the reports in the Task folder carry the context.
