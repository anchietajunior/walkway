# Verification confronts the tech spec with the code

Verification takes the tech spec as the truth and the code as the claim. It traces every Acceptance Criterion, Contract, Decision and changed file between the two before the formal verification, and it reads the reports of Development, the Simplifier and the Code Reviewer only for their answers to its own earlier findings. Before this, Validation started from the Development and Code Review reports and confronted their claims, so a decision that drifted from the requirements during development could pass. For this to work, the tech spec carries a Technology half with Contracts that the code can be checked against, while names and code shapes stay with Development. The cost is a longer Planning, and a tech spec error that only an Escalation can fix, because no agent after Planning changes the tech spec.
